  grid before claiming a general advantage. Momentum/Nesterov still differ.

  width-384 model as if they were the same experimental setting.

## MuonH is not generally MCSD on a Frobenius sphere

The constraint and return map coincide in this comparison, but the oracle
input does not. Let `P_X` be the Frobenius-orthogonal tangent projector,
`N_R(Y) = R Y / ||Y||_F`, and temporarily give all methods the same momentum
matrix M. The implemented MuonH adapter uses

`N_R(X - eta R msign(M) / ||msign(M)||_F)`.

MCSD uses `Q=P_X M` and `N_R(X - eta c msign(Q))`; MCSD-TP additionally
projects that sign direction before the radial return. In this experiment
`c=R/sqrt(min(m,n))`. For exact full-rank sign, MuonH's normalization gives
that same c, so the main mathematical difference is not a missing constant:
it is the tangent projection **before** the nonlinear matrix sign.

Radial return has first-order action `P_X`, but generally
`P_X msign(M) != P_X msign(P_X M)`. A concrete exact-arithmetic check uses
`X=diag(2,1)`, `R=sqrt(5)`, and `M=diag(3,0.5)`. Then
`Q=diag(0.4,-0.8)`, with `<Q,-msign(M)>=+0.4` and
`<Q,-msign(Q)>=-1.2`. Thus an ambient-Muon direction need not minimize the
tangent linear model, even with the same norm ball and return. This example
illustrates non-equivalence, not a prediction of MuonH's practical loss.

MuonH therefore does not automatically satisfy the paper's small-error LMO
condition for `P_X M`; an arbitrary sufficiently large oracle-error allowance
would not justify the useful small-error bound. Do not describe MuonH as a
covered MCSD special case merely because both normalize back onto a sphere.

There is, however, a conditional inexact-oracle interpretation. For the
same M, exact full-rank sign, matched step scaling and no Nesterov, set
`Q=P_X M`, `S_H=-msign(M)`. Duality gives the directly derived bound
`0 <= zeta_H = <Q,S_H> + ||Q||_* <= 2 ||M-Q||_*`, where `*` is the nuclear
norm. Thus this idealized MuonH can be written as an inexact-MCSD update;
the useful theorem still requires control of this error and all its other
assumptions. With a different oracle input B (such as Nesterov), the analogous
bound is `2 ||B-Q||_*`. The bound does not automatically cover an infeasible
finite-step matrix sign: the actual oracle direction must first satisfy its
norm constraint. These are algebraic observations, not a new convergence
proof for the complete practical MuonH recipe.

For strictly scale-invariant losses without momentum, the current gradient
may already be tangent, making the idealized MCSD and MuonH projection step
coincide under the appropriate full-rank scaling. That special case does not
make accumulated ambient momentum tangent at the current iterate in general.

Sources: the user's `main1.tex`, shared update and Algorithms 1/2; local
`manifold_baselines.py` and `manifold_mcsd.py`; [Hyperball Section 2,
equation (1)](https://arxiv.org/html/2606.16899v1#S2).

Future attribution should match momentum/Nesterov and the actual step norm,
then compare no input TP, input TP only, and input plus output TP. A win by a
baseline at one untuned learning rate is not evidence that the two algorithms
are equivalent, nor proof of which component explains the loss difference.
