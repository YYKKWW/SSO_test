## 2. 这组实验应支持什么主张

论文 Algorithms 1/2 的共同机制是：当前样本更新 ambient EMA，先切投影，再解
ambient norm-ball LMO；MCSD 对 trial 做局部 metric projection，MCSD-TP
额外投影 LMO 输出后做 retraction。论文的不精确 LMO 条件还要求方向范数可行。

建议让实验 3 回答三个问题：

1. 同一实现框架能否在 Frobenius 球面、scaled Stiefel、谱球面上稳定训练真实 LM？
2. 在同约束、同网络、同数据预算下，MCSD/TP 是否具有可复现的质量或时间优势？
3. 收益是否与前置/后置切投影有关，而非仅来自不同步长、动量或数值精度？

PCA/Brockett 负责驻点、动量和 oracle 误差的受控验证；Dense LM 负责实际效用。
LM 验证损失下降不是 `O(T^-1/4)` 收敛速率的验证。当前三几何代码不含论文
Algorithm 3 的 closed-set PGD 分支，因此也不能宣称验证了其非光滑保证。
若闭集推广是最终摘要中的主要贡献，应另外保留一个具有真实分支切换的小规模
闭集实验；无需为此把 PGD/gap 搜索重新塞回本轮 LM 主实验。

## 3. 推荐模型与数据预算

优先完整完成中间规模，而不是一开始展开所有规模、几何、精度和学习率的乘积。

| 用途 | 层数 | width / FFN | Q heads / KV groups | 矩阵参数估计 |
| --- | --- | --- | --- | --- |
| 可选小规模复核 | 28 | 256 / 768 | 4 / 2 | 73.400M |
| 主实验，当前配置 | 28 | 384 / 1152 | 6 / 3 | 126.616M |
| 可选规模迁移 | 28 | 512 / 1536 | 8 / 4 | 190.841M |

共同设置：head dimension 64，GQA，SwiGLU，QK norm，RMSNorm，RoPE base
`1e6`，无 bias/dropout，sequence length 2048，untied embedding/head，暂按
padded vocabulary 100352 计算。它们是研究用 Qwen3-style decoder，不是官方
预训练模型。上述估计为 `28 * 12*d^2 + 2*100352*d`，不含归一化参数；最终以
实例化模型清单为准。小/大配置已实现，但不代表其 3B 训练已完成。

全局 batch 128，每步 `128*2048=262144` tokens。每组 3B 对应 11445 步，
实际为 3,000,238,080 tokens。约 127M 模型的 tokens/parameter 约 23.7；
这只是预算说明，不是充分训练或已收敛的证明。较大规模的该比值更低，不能
仅凭一个固定比值断定算法失败原因。

直接使用 H20 已有 3B 训练索引，不把原 1B 样本重复三遍而称为 3B 独立数据。
检查真实可用 tokens、数据混合比例、tokenizer revision 和训练/验证/最终评估
split。累计预算可能需要末尾少量重采样，必须披露实际 token 数及重复量。
原 1B 主表的模型、序列长度和矩阵拆分不同，不能直接并入这张新主表。

## 4. 对比矩阵与公平性

| 同约束主比较 | 本文方法 | 主要强基线 |
| --- | --- | --- |
| Frobenius 球面 | MCSD-F、MCSD-TP-F | MuonH / Hyperball 的明确版本 |
| scaled Stiefel | MCSD-St、MCSD-TP-St | iMuon；按论文说明 ambient-momentum 适配 |
| 谱球面 | MCSD-S、MCSD-TP-S | SSO、MuonSphere |

另设 AdamW、MuonW 为无约束应用参照，不将其排名解释为相同可行集上的算法结论。
核对论文已引用 MACRO 与 MCSD 的公式关系：若确为同一更新，不重复包装成新基线；
若有实质区别，明确区别并选择最接近的可复现对照。Stiefel 的 RSGD 可作为便宜
的机制参照，是否进入主表按预算决定。

同约束比较统一网络、逻辑矩阵、初始化、半径、辅助 AdamW、数据顺序及评估。
每层受约束对象为完整 Q/K/V/O/gate/up/down 共七个组件，不再按 attention head
拆分。28 层共 196 个逻辑矩阵。embeddings/head/norm 不归
新矩阵 optimizer；约束矩阵 WD=0，辅助参数的 WD 按参数组设置。

Stiefel 改变矩阵的全部奇异值，跨几何不能具有相同初始权重或相同可行函数类。
主结论必须优先来自同约束比较。对基线有两种证据需要区分：保留作者原生版本
用于应用比较；共同组件/动量/返回的适配版本用于机制归因。对适配显式命名，
不要把修改后的方法写成原论文未改动的实现。

同一 LR 数值不等于公平。各方法拥有相同搜索预算、边界扩展规则和独立评估流程。
建议沿用六个开发候选的上限：先校准各方法的 LR 中心，再用三个对数间隔 LR
和两个预先确定的次参数值；不允许只给本文方法追加无限搜索。

## 5. 主训练采用实用精度，不强制逐步 full SVD

- 通用方向：BF16 matrix-sign / Polar Express，FP32 master weight 和 EMA。
- Frobenius 返回：FP32 norm scaling，无需 SVD。
- Stiefel 返回：有限次 polar/msign 加 FP32 polishing，记录正交约束误差。
- 谱球面：PI 和近似返回作为实用版本，分别记录范数误差与方向误差；MCSD 的
  top-8 近似 projection 与 MCSD-TP 的 radial return 不能混称同一映射。
- full SVD：固定样本矩阵、少量短对照和稀疏诊断的参考，不作为每个正式运行的
  强制逐步开销。诊断频率、抽样覆盖和时间单列。

近重奇异值按作者要求继续计算并记录，不因 gap 小而退出，不静默切换 PGD。
这是一项经验实现决定，不会使奇异点自动具有唯一切空间。

不能把有限步 polar 的约束残差，或 PI/top-8 的球面偏差，描述成严格投影。
`main1.tex` 的 LMO 误差项不覆盖不可行返回。现有合成矩阵上约 1.5% 的
PI/top-8 球面偏差只是风险提示，不代表所有训练矩阵；需在真实 LM 状态抽样。
优先使用约束误差小、质量/成本合理的实用变体，而不是无限提高精度。

## 6. 最有价值的机制实验

**优先做 Frobenius 球面的 2x2 切投影消融。** 同一 EMA、LMO、尺度和径向返回，
分别打开/关闭输入切投影与输出切投影：两者关、仅输入开(MCSD)、仅输出开、
两者开(MCSD-TP)。该消融不是对原生 MuonH 的重新命名。

先做同一 checkpoint、同一梯度和动量的单步对照，记录法向分量、实际更新角度、
步长与局部下降；再做独立短训练。匹配有效步长后再看收益是否仍在，避免把
隐式缩小步长误称为几何改进。

**精度消融分开两个来源。** 固定返回只改变 LMO 精度；固定 LMO 只改变返回精度。
在小预算上与 SVD 参考比较方向线性误差、约束偏差、loss 和时间，而不是只
展示近似版本快了多少。Stiefel 分别报告方形和矩形组件，不人为制造 MCSD/TP 差异。

## 7. 执行顺序与资源

| 阶段 | 目标 | 不允许据此声称什么 |
| --- | --- | --- |
| H20 短检查，最多 100 steps | 真实模型构建、梯度、参数组、约束、恢复、时间 | 方法优于基线 |
| 等预算开发，100M 筛查与 1B 选参 | 排除坏配置、确定 LR 区间与实现版本 | 3B 的最佳 LR 已被证明 |
| 约 127M、3B、三个独立配对种子 | 冻结版本与参数，得到主表、主曲线 | 对任意规模普遍占优 |
| 可选 73M/191M、3B 的关键对照 | 测试规模迁移 | 未测试几何或方法同样有益 |

若由 1B 选参后直接做 3B，称为预算迁移协议；若主张各方法在 3B 下充分调优，
应给所有方法相同的 3B 开发候选预算。正式测试集不能参与选择。

三几何主矩阵共 10 个方法/几何组合；三个种子为 30 个 3B 作业、90B 累计
processed tokens。再加 AdamW/MuonW 是 36 个作业、108B tokens，尚未计调参
与消融。因此先测每组稳定 steps/s，再决定规模复核数量；不预先承诺总天数。
这是规划总量，不是本次提交授权或已提交清单。

沿用作者希望预留公共资源的原则：通常 4--6 张 H20 并行、硬上限 8 张；小模型
先单卡一个作业。使用多卡时保持全局 batch 不变，报告总 GPU-hours，而不是
把 GPU 数翻倍导致的墙钟缩短称为优化器加速。

## 8. 论文中的最小结果包

1. 主表：按几何分组的最终 held-out NLL/PPL，三个种子原值、均值和离散程度，
   配对基线差值，GPU-hours、tokens/s、峰值显存、失败情况。
2. 主图：每几何一列，NLL 对 processed tokens 和实际时间两个视角；标明各方法
   各自冻结的最优开发 LR。不通过裁掉早期曲线或只取有利 checkpoint 隐藏劣势。
3. 机制图/表：2x2 投影消融以及 LMO/返回误差与时间分解。细节放附录。
4. 稳健性：LR 邻域、配对种子和预先选择的规模/预算复核。三个种子是最低建议，
   不是 ICML 的固定规定；微小提升需增加独立重复，不能用 token 级误差条替代种子波动。

主终点为相同 token 预算的最后 checkpoint，不按测试 NLL 选择 checkpoint。
验证集用于选参；最终使用未参与调参的 held-out 集。至少保存 train/val loss、
完整配置、数据标识、R/scale 清单和计时。后续需要 downstream claim 时再增加
预先选定的少数任务；仅支持语言建模 loss 的结论不必堆叠大量低功效 benchmark。

## 9. 项目收敛到最小可复用结构

保留现有 Megatron 的 model/data/training，新增部分以 optimizer、geometry、
logical layout 为中心。BF16 转换前初始化、FP32 master 元数据、参数组路由
这几处小型训练适配是必要的，不等于另造训练框架。

H20 可以直接复用原来存在的 Megatron 源码与环境，不需要每次重新克隆。
但新 optimizer 必须确实被加载，不能仅把 `PYTHONPATH` 指向原项目而无意加载旧类。
每个运行记录 `module.__file__`、关键文件 SHA、外部源码真实路径、环境版本和
差异补丁。Git 未追踪不妨碍当场运行，但不足以让别人重建相同实验。

已实现与下一轮工程优先级：

1. 已恢复并追踪运行所需源码；新 H20 独立目录复用旧环境和数据，不修改旧源码。
2. 已实现 smoke/pilot/tune/main、tokens、数据 prefix、模型配置与安全 dry-run。
3. 已接入 geometry-matched 基线、共同初始化、辅助参数协议及实际参数清单。
4. 完成 H20 短训练与恢复核验后，再安排受资源预算约束的调参和主实验队列。

不为此删除旧探索、不改动论文复现冻结库、不把旧不同架构结果合并进新表。

## 10. 投稿表述与引用

近似 oracle 与两类返回的统一研究，而不是重新声称首先把 MCSD 用于语言模型。
